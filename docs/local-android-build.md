# Building CoinFlow on your own machine and running it on your phone

A plain-language, step-by-step guide for building the app **locally** (on your Windows 11 laptop)
instead of on Expo's cloud, and installing it on a **physical Android phone** — over USB **or
wirelessly**.

Written for someone who has just installed Android Studio and hasn't done Android development
before. Follow it top to bottom the first time. After that, only **Part 4** matters day to day.

*Last reviewed: 2026-09 · Expo SDK 57 · React Native 0.86 · Android Studio 2025.1+ ·
command-line tools rev 19+ (the new `android` CLI, `sdkmanager` deprecated).*

### Versions this project expects (2026)

You don't have to memorise these — the steps below install them — but if a build complains about
a version, this is the reference:

| Piece | Version | Why |
|---|---|---|
| Node.js | **22 LTS** (20.19.4+ or 24.3+ also OK) | RN 0.86 `engines` field |
| Java (JDK) | **17** (Temurin) | matches Expo's SDK 57 cloud image; see the TODO in 1.2 about moving to 21/25 |
| Android API / Platform | **36** | Expo SDK 57 `compileSdk`/`targetSdk` |
| Build-Tools | **36.0.0** | " |
| NDK | **27.1.12297006** | reanimated / worklets compile C++ |
| CMake | 3.22.1+ | " |
| Gradle | 9.x (wrapper, auto-downloaded) | generated by prebuild — nothing to install |
| Android Gradle Plugin | 8.x | " |

New Architecture (bridgeless) and Hermes are **on by default** in SDK 57 — there is nothing to
configure or toggle. If you see "bridgeless" in logs, that's expected.

## 0. What we're doing, and why

CoinFlow is a **custom native app**. It has a small piece of Kotlin code (`modules/coinflow-sms/`)
that listens for incoming SMS, plus the Expo **dev client**. Because of that:

- **The "Expo Go" app cannot run CoinFlow.** It only runs plain JavaScript apps.
- We need to **compile** the app ourselves into an `.apk` (an Android app file) and install it.

There are two ways to compile:

| Way | What it is | Do we use it? |
|---|---|---|
| **EAS cloud build** (`eas build`) | Expo compiles it on their servers, you download the result. | Works, but slow (long free-tier queue) and you already hit their outages. |
| **Local build** (`npx expo run:android`) | Your laptop compiles it, using the Android tools from Android Studio, and installs it straight onto your connected phone (USB or Wi-Fi). | **Yes — this guide.** Faster feedback, no queue, no upload. |

> **Note on `eas build --local`:** that command only works on macOS and Linux, **not Windows**.
> On Windows the equivalent is `npx expo run:android`, which is what we use here. (If you ever
> really want `eas build --local`, you'd have to install WSL2 + the Android SDK inside Ubuntu —
> see Part 7. Not worth it for normal development.)

### The big picture of what `npx expo run:android` does

When you run it, four things happen in order:

1. **Prebuild** — Expo generates a native `android/` folder from `app.json` + the config
   plugins (this is where your SMS permissions and the `<receiver>` get written into the Android
   manifest). This folder is disposable and is **git-ignored** — never commit it.
2. **Gradle build** — Android's build tool (Gradle) compiles the Java/Kotlin/C++ and your JS
   bundle into `app-debug.apk`. First time: 15–40 min and ~1–2 GB of downloads. After that:
   1–5 min.
3. **Install** — it pushes the `.apk` onto your connected phone (USB or Wi-Fi).
4. **Start Metro** — the JavaScript dev server starts so the app can load your code and
   hot-reload it as you edit.

Local builds use the **files currently on your disk** (not git), so uncommitted changes are
included.

## Part 1 — One-time computer setup

You do this section **once**. Open **Windows PowerShell** for the commands.

> **2026 tip — install with `winget`.** Windows 11 ships with `winget` (Windows Package Manager).
> It downloads, installs *as admin*, and puts things in the standard system locations — no
> hunting for installers, no user-mode-install surprise. Every install step below gives a
> `winget` line first and the manual download second.

### 1.1 Node.js

```powershell
node --version      # want v22.x  (v20.19.4+ or v24.3+ also fine)
```

If it's missing or older:

```powershell
winget install OpenJS.NodeJS.LTS
```

(or the LTS installer from <https://nodejs.org>). You've been running `npm` already, so this is
almost certainly fine.

### 1.2 Install Java 17 (JDK)

Android's build needs **JDK 17** — not 21, not 11 (see the TODO below about revisiting this).

```powershell
winget install EclipseAdoptium.Temurin.17.JDK
```

`winget` installs it system-wide to `C:\Program Files\Eclipse Adoptium\jdk-17.x-hotspot\` and
runs elevated automatically.

Manual alternative: the `.msi` from
<https://adoptium.net/temurin/releases/?version=17> — but **right-click ▸ "Run as
administrator"**, otherwise it silently installs to
`C:\Users\<you>\AppData\Local\Programs\Eclipse Adoptium\...` and you must use *that* path in 1.4.

> **You won't "see" it anywhere.** Temurin adds no Start Menu tile, no desktop icon, no entry in
> most "apps" lists — it's just a folder of files. The only ways to confirm it's installed:
> **Settings ▸ Apps ▸ Installed apps** and search "Temurin", or check whether the folder above
> exists. Making the tools use it is step 1.4 (setting `JAVA_HOME`); until you do that, typing
> `java -version` will still show whatever Java was already on your machine.

> You *can* instead point at the JDK bundled inside Android Studio
> (`C:\Program Files\Android\Android Studio\jbr`), but recent Android Studio ships JDK 21, which
> can cause odd Gradle errors with this React Native version. Installing Temurin 17 is the
> reliable path.

> **💡 Future improvement (TODO):** JDK 17 is pinned here only because it's the version Expo's
> SDK 57 cloud build image uses and the version RN 0.86 officially supports. Newer Temurin LTS
> releases (21, and later 25) may well build CoinFlow fine. **Someday:** install the latest
> Temurin LTS, point `JAVA_HOME` at it, run a clean `npx expo prebuild --clean && npx expo
> run:android` plus an `eas build`, and if both pass, drop the JDK 17 requirement (update this
> section, `docs/sentry-and-ci.md` if it mentions it, and uninstall JDK 17). Re-check whenever we
> bump the Expo SDK — the supported JDK usually moves with it.

### 1.3 Install Android Studio + the SDK pieces

If Android Studio isn't installed yet:

```powershell
winget install Google.AndroidStudio
```

Launch it once and let the first-run wizard finish (it installs a default SDK). Then pick
**one** of the two ways below to get the exact packages CoinFlow needs.

**Note your "Android SDK Location"** — shown at the top of the SDK Manager, usually
`C:\Users\<you>\AppData\Local\Android\Sdk`. You need it in 1.4.

#### Option A — the SDK Manager window (click-based)

**Android Studio ▸ (welcome screen) More Actions ▸ SDK Manager**, or in a project
**Settings ▸ Languages & Frameworks ▸ Android SDK**.

- **"SDK Platforms" tab:** tick **Android API 36**.
- **"SDK Tools" tab:** tick **"Show Package Details"** (bottom-right), then:
  - **Android SDK Build-Tools** → `36.0.0`
  - **NDK (Side by side)** → `27.1.12297006`  *(C++ toolchain — reanimated/worklets need it)*
  - **CMake** → newest listed (`3.22.1`+)
  - **Android SDK Command-line Tools (latest)**
  - **Android SDK Platform-Tools**  *(contains `adb`)*
  - **Android Emulator** — optional (you're on a real phone)

Click **Apply**. Ticking a package here also accepts its license (that's why step 1.5 is
usually a no-op).

#### Option B — headless, with the new `android` CLI (2026)

The command-line tools rev 19+ replaced `sdkmanager` with a self-updating **`android`** binary
(`android sdk install/update/remove/list`). After 1.4 has set `ANDROID_HOME` and PATH, one line
does everything:

```powershell
android sdk install --no-metrics `
  "platforms;android-36" `
  "build-tools;36.0.0" `
  "platform-tools" `
  "ndk;27.1.12297006" `
  "cmake;3.22.1"
```

It prompts once to accept the licenses (`y`). `--no-metrics` opts out of usage analytics.
(The old `sdkmanager` still runs but prints a deprecation warning — see 1.5.)

### 1.4 Set environment variables (so the tools can find each other)

Paste this into **PowerShell**, editing the two paths if yours differ (from step 1.2 and 1.3):

```powershell
# --- Android SDK location (from the SDK Manager window) ---
[Environment]::SetEnvironmentVariable("ANDROID_HOME", "$env:LOCALAPPDATA\Android\Sdk", "User")

# --- Java 17 location: look in BOTH the system-wide and the per-user install folders ---
$jdk = (
  Get-ChildItem "C:\Program Files\Eclipse Adoptium", "$env:LOCALAPPDATA\Programs\Eclipse Adoptium" -Directory -ErrorAction SilentlyContinue |
  Where-Object Name -like "jdk-17*" | Select-Object -First 1
).FullName
if (-not $jdk) { Write-Error "No Temurin JDK 17 folder found — check where the installer put it." }
[Environment]::SetEnvironmentVariable("JAVA_HOME", $jdk, "User")

# --- add the tool folders to your PATH (JDK bin goes FIRST so `java` = 17) ---
$sdk  = "$env:LOCALAPPDATA\Android\Sdk"
$path = [Environment]::GetEnvironmentVariable("Path", "User")
foreach ($d in @("$sdk\platform-tools", "$sdk\cmdline-tools\latest\bin", "$sdk\emulator")) {
  if ($path -notlike "*$d*") { $path = "$path;$d" }
}
if ($path -notlike "*$jdk\bin*") { $path = "$jdk\bin;$path" }
[Environment]::SetEnvironmentVariable("Path", $path, "User")
```

> If another Java was already installed (Oracle, or the one bundled with some apps), a bare
> `java -version` in a new terminal **may still show that older one** — Windows searches the
> system-wide PATH before your user PATH. That's fine: the Android build reads **`JAVA_HOME`**,
> not `java` on PATH. Confirm the *build's* Java with
> `& "$env:JAVA_HOME\bin\java.exe" -version` (should say `17.0.x`). Only if a tool complains
> about the Java version do you need to also fix the system PATH (Start ▸ "Edit the system
> environment variables") or uninstall the old JDK.

**Close and reopen PowerShell** (and VS Code, if open) so the new variables take effect.

### 1.5 Accept the Android SDK licenses

**If you installed the SDK pieces through Android Studio's SDK Manager (step 1.3), the licenses
are already accepted — you can skip this step.** Ticking packages in that window accepts their
licenses for you.

**Verify** (optional):

```powershell
Get-ChildItem "$env:ANDROID_HOME\licenses"
```

If you see `android-sdk-license` (and usually `android-sdk-preview-license`) listed, you're done.

> **About the old `sdkmanager --licenses` command:** newer command-line tools (revision 19+,
> shipped 2025) **deprecated `sdkmanager`** and replaced it with a self-updating `android`
> binary. Running `sdkmanager --licenses` now just prints:
> *"WARNING: The SDK Manager CLI tool (sdkmanager) is deprecated… The `--licenses` option is no
> longer needed."* — that's **not an error**, it's telling you the step is obsolete. The new
> equivalents are `android sdk list`, `android sdk install "<package>"`, `android sdk update`
> (license prompts happen inline when installing). Add `--no-metrics` if you don't want the tool
> phoning home.
>
> If a build ever *does* complain `You have not accepted the license agreements`, the simplest
> fix is: open **Android Studio ▸ SDK Manager**, let it show any "not accepted" items, click
> **Apply**. That rewrites the `licenses\` files.

### 1.6 Verify everything

```powershell
node --version                             # v22.x  (or 20.19.4+ / 24.3+)
& "$env:JAVA_HOME\bin\java.exe" -version   # must say "17.0.x"  — this is the one the build uses
adb --version                             # "Android Debug Bridge version 1.0.xx"
android sdk list "ndk*"                    # confirms the CLI works + shows the NDK is installed
android sdk list "cmake*"                  # ...and CMake  (android sdk list takes ONE pattern)
echo $env:ANDROID_HOME                     # your SDK path
echo $env:JAVA_HOME                        # your JDK 17 folder
```

(A bare `java -version` may still report an older Java — see the note in 1.4. What matters is
that `$env:JAVA_HOME\bin\java.exe` is 17.)

Then, from the project folder:

```powershell
cd D:\IISc\Projects\coinflow
npx expo-doctor
```

`expo-doctor` checks the project for common problems (it's still its own package —
`npx expo-doctor` — not an `npx expo` sub-command). A few warnings are OK; hard errors it prints
in red should be fixed before building.

## Part 2 — One-time phone setup

### 2.1 Turn on Developer Options

On the phone: **Settings ▸ About phone ▸ Build number**. Tap **Build number** 7 times.
It says "You are now a developer!".

(On some phones Build number is under **Settings ▸ About phone ▸ Software information**.)

### 2.2 Turn on debugging

**Settings ▸ System ▸ Developer options** (on Samsung: **Settings ▸ Developer options**):
- Enable **USB debugging**.
- Enable **Wireless debugging** if you want the cable-free path in 2.3b.
- Enable **Install via USB** if your phone has it (Xiaomi/Oppo/Vivo do).

### 2.3a Connect over USB (simplest)

1. Plug the phone into the laptop with a **data-capable USB cable** (some cables are
   charge-only and won't work).
2. On the phone, a dialog pops up: **"Allow USB debugging?"** — tick **"Always allow from this
   computer"** and tap **Allow**.
3. Check the laptop sees it:

   ```powershell
   adb devices
   ```

   You want:

   ```
   List of devices attached
   ABCD1234XYZ     device
   ```

   - `unauthorized` → you didn't tap **Allow** on the phone. Unplug, replug, watch for the popup.
   - Nothing listed → try another cable / USB port; on Xiaomi/Oppo also enable "Install via USB".

### 2.3b Connect wirelessly (Android 11+, no cable) — the 2026 default for many

Phone and laptop must be on the **same Wi-Fi**.

1. Phone: **Developer options ▸ Wireless debugging ▸** turn on ▸ tap **"Pair device with
   pairing code"**. It shows an **IP address & port** and a **6-digit code**.
2. Laptop:

   ```powershell
   adb pair 192.168.x.x:XXXXX      # the IP:port from the "pair" dialog
   # enter the 6-digit code when asked
   ```

3. Then connect using the **main** Wireless-debugging screen's IP:port (different port from the
   pairing one):

   ```powershell
   adb connect 192.168.x.x:YYYYY
   adb devices                     # should list  192.168.x.x:YYYYY   device
   ```

Pairing is one-time; afterwards just `adb connect …` (until the phone reboots or changes
network). A first USB connection also "primes" wireless — after that `adb tcpip 5555` +
`adb connect <ip>:5555` works too.

## Part 3 — Build and run CoinFlow (first time)

From the project root, in your reopened PowerShell:

```powershell
cd D:\IISc\Projects\coinflow

# 1. make sure JS dependencies are installed
npm install

# 2. build the app, install it on the phone, and start the dev server
npx expo run:android
```

What you'll see:

- `› Building app…` and a long stream of Gradle `> Task :…` lines. **First run is 15–40 min.**
  Let it work. It's downloading Gradle, the Android build plugin, and compiling native code
  (including your `coinflow-sms` module).
- It targets whatever `adb devices` shows — your USB **or** wirelessly-connected phone. If more
  than one device/emulator is listed it asks which; or pick up front with
  `npx expo run:android --device`.
- When it finishes: the **coinflow** app opens on your phone by itself, and the terminal now
  shows the **Metro** dev server ("Waiting on http://localhost:8081", a QR code, a menu).

The app right now is just a placeholder Home screen ("CoinFlow — Home coming soon"). That's
expected — the screens get built in the next implementation steps. What matters is that it
**builds, installs, and launches**.

Leave the Metro terminal running while you work. Press `r` in it to reload the app, `j` to open
the debugger, `m` to toggle the dev menu.

## Part 4 — Everyday workflow (after the first build)

This is the part you'll actually use repeatedly.

### If you only changed JavaScript / TypeScript / styles / images

**No rebuild needed.** Just run the dev server:

```powershell
npx expo start --dev-client
```

Then open the **coinflow** app on your phone (with the phone on the **same Wi-Fi** as the
laptop, or still plugged in via USB). It connects to Metro and your changes hot-reload in a
second or two. Save a file → the app updates.

If it doesn't connect, with the phone plugged in run:

```powershell
adb reverse tcp:8081 tcp:8081
```

then reopen the app.

### If you changed anything "native", you must rebuild

Run `npx expo run:android` again. "Native" changes are:

| Changed… | Rebuild? |
|---|---|
| Anything in `modules/coinflow-sms/` (the Kotlin files, `app.plugin.js`) | **Yes** |
| `app.json` (permissions, plugins, name, icons, package) | **Yes** |
| Added / removed / upgraded a dependency that has native code (any `expo-*`, `react-native-*`) | **Yes** |
| `package.json` `main`, `babel.config.js`, `metro.config.js` | Usually yes (safest to rebuild) |
| `.ts` / `.tsx` / `.js` app code, JSON, assets, `src/**` | No — just Metro |

### Force a clean rebuild (when things act weird)

```powershell
npx expo prebuild --clean        # deletes and regenerates the android/ folder
npx expo run:android
```

or simply delete the `android` folder and run `npx expo run:android` again.

## Part 5 — Getting an `.apk` file you can share or keep

After a successful `npx expo run:android`, the installable file is at:

```
D:\IISc\Projects\coinflow\android\app\build\outputs\apk\debug\app-debug.apk
```

You can copy that to another phone and install it (that phone needs "Install unknown apps"
allowed for your file manager). This is a **debug** APK — it needs Metro running to load JS
unless you also bundle it, and it's signed with a throwaway debug key. A proper standalone
**release** APK (self-contained, signed for distribution) is a later concern covered by the
`SPEC/PLAN.md` §12 step 7 "Ship" task; don't worry about it now.

## Part 6 — Troubleshooting

| Symptom | Fix |
|---|---|
| `winget` not recognised | Update **App Installer** from the Microsoft Store (Win11 has it; older builds may not). Or use the manual download in each step. |
| `SDK location not found` / `ANDROID_HOME is not set` | Env var missing or terminal not restarted. Redo **1.4**, open a fresh PowerShell. (`ANDROID_SDK_ROOT` is the old name — set **`ANDROID_HOME`**.) |
| `You have not accepted the license agreements` | Open **Android Studio ▸ SDK Manager ▸ Apply** (accepts pending licenses, rewrites `%ANDROID_HOME%\licenses\`), or run the `android sdk install …` line from **1.3 Option B** and press `y`. The old `sdkmanager --licenses` is deprecated — see **1.5**. |
| Build fails with `Unsupported class file major version` / `invalid source release: 17` / `Dependency requires ... Java 17` | Wrong JDK is being used. Confirm `& "$env:JAVA_HOME\bin\java.exe" -version` says **17**; redo **1.4** so `JAVA_HOME` points at the Temurin 17 folder; reopen the terminal. A bare `java -version` showing something else is OK as long as `JAVA_HOME` is 17. |
| `NDK not found` / `No version of NDK matched the requested version` | Install **NDK 27.1.12297006** — SDK Manager (**1.3 Option A**) or `android sdk install "ndk;27.1.12297006"` (**Option B**). |
| `CMake ... was not found` | `android sdk install "cmake;3.22.1"` (or tick CMake in SDK Manager). |
| Gradle fails with `Java heap space` / `OutOfMemoryError` | Close Chrome / other heavy apps and retry; the build wants ~4–8 GB free RAM. |
| `adb devices` shows `unauthorized` | Tap **Allow** (+ "Always allow from this computer") on the phone. Unplug/replug or re-run `adb connect` to re-trigger the prompt. |
| `adb devices` shows nothing (USB) | Charge-only cable, dead port, or missing OEM driver. Try another cable/port; on Xiaomi/Oppo/Vivo also enable **Install via USB**. |
| Wireless device shows `offline` / drops after a while | Phone changed Wi-Fi or slept. Re-run `adb connect <ip>:<port>`. If pairing is lost (phone reboot), redo `adb pair` (**2.3b**). |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` / `signatures do not match` | An old copy is installed. `adb uninstall com.ckworkforce.coinflow`, then rebuild. |
| App opens but shows **"Could not connect to development server"** (red screen) | Metro isn't running or unreachable. Start `npx expo start --dev-client`; on USB run `adb reverse tcp:8081 tcp:8081`; on Wi-Fi make sure `adb devices` still lists the phone and both are on the same network. |
| Windows firewall popup for **Node.js** on first `expo start` | Click **Allow access** (at least Private networks) so the phone can reach Metro. |
| Build errors about long paths (`Filename too long`) | In an **admin** PowerShell: `git config --system core.longpaths true`; also enable Windows long paths (Settings ▸ search "long paths" ▸ on). |
| `expo run:android` picks an emulator instead of the phone | `npx expo run:android --device` and choose your phone. |
| It opened the **Expo Go** app, not CoinFlow | Expo Go can't run this app. Open the **coinflow** app icon directly. |

## Part 7 — (Optional) `eas build --local` via WSL2

Only if you specifically want to reproduce the **cloud** build on your machine. `eas build
--local` needs Linux or macOS.

1. Install **WSL2** with Ubuntu: in an admin PowerShell, `wsl --install`, reboot.
2. Inside Ubuntu: install Node 22 (`fnm` or NodeSource), Java 17 (`sudo apt install
   openjdk-17-jdk`), and the Android **command-line tools**; set **`ANDROID_HOME`** (the old
   `ANDROID_SDK_ROOT` still works but is deprecated). Install SDK packages with the new CLI:
   `android sdk install "platforms;android-36" "build-tools;36.0.0" "platform-tools"
   "ndk;27.1.12297006" "cmake;3.22.1"`.
3. Clone the repo *inside* the WSL filesystem (`~/coinflow`, **not** `/mnt/d/...` — that's slow),
   `npm install`, then:
   ```bash
   npx eas-cli build --profile development --platform android --local
   ```
4. The finished `.apk` lands in the project folder. Install it with `adb install -r <file>.apk` —
   attach the phone to WSL with **`usbipd-win`** (`winget install dorssel.usbipd-win`), or just
   copy the `.apk` to Windows and run the Windows `adb`.

For day-to-day work, **`npx expo run:android` from Windows (Parts 3–4) is simpler and faster** —
use that unless you have a concrete reason not to.

## Appendix — CoinFlow-specific facts to remember

- **Package name / app id:** `com.ckworkforce.coinflow`. Uninstall with
  `adb uninstall com.ckworkforce.coinflow`.
- **This is a dev-client build.** It contains the Expo dev menu (shake the phone or press `m` in
  Metro). It is *not* the same as Expo Go.
- **`android/` and `ios/` are generated** by prebuild and are in `.gitignore`. If you see them in
  `git status`, something added them by mistake — don't commit them.
- **The `coinflow-sms` native module** is picked up automatically (Expo autolinking finds
  anything under `modules/` with an `expo-module.config.json`). No manual linking.
- **SMS permissions** (`RECEIVE_SMS`, `READ_SMS`) are declared in the manifest via the module's
  config plugin. The app will ask for them at runtime in a later step; for now nothing prompts.
- **`.easignore`** only affects EAS *cloud* builds. Local builds ignore it.
- **Local builds use your working tree**, so you don't have to commit before building — but do
  commit before an **EAS** build, because that one uploads from git.
