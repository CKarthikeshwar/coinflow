CoinFlow — design prototype

One direction: Midnight — a dark, calm, black-and-white app that disappears, faithful to the reference screens in design-references/. Static HTML/CSS, no JS. Read at 390 × 844. Everything lives in two files: screens.html (the tab / flow screens) and p0-screens.html (the P0 detail screens).

Spec changes folded into this build (and written into SPEC-UI-UX.md):
  • No colour on any foreground element. Black / white / grey. Direction and state are carried by the always-present +/− sign, by weight and size, and by fill vs hairline — never hue. Two ambient exceptions (V-11): the Analytics “Where it went” breakdown, and a faint cool blue-grey wash on the app ground (a glow behind the top of each screen).
  • Hero = Balance. The big figure is the month's Balance = Income − Spent (a computed net for the period, not an account balance from SMS — SPEC D2 revised); Income and Spent show as its components. The “so far” tag is gone.
  • The Note is the card label (a short one-line label); a Description (optional) field holds longer detail (Details screen). When there's no note the label falls back to the Account, then “No note”.
  • “Account” reintroduced (the old “merchant / person”, renamed). The payee / payer — a name or a UPI address. Not on the card; on Details + the Add/Edit sheets. It drives auto-categorisation memory: account → category rules (F8 un-parked), surfaced in the Add sheet's account autocomplete and in Settings › Account rules.
  • Card layout (per design-references/1.png, 3.png): each transaction is its own rounded card with a category icon tile on the left (income tiles invert). Day headers are plain labels between card groups. The Review Queue stays a flat list with payment-method icon tiles (4.png).
  • No time of day on the Transactions list (the day header carries the date). Home “Recent” keeps a relative time (“2h ago”).
  • One colour carve-out. The Analytics “Where it went” category breakdown (dot / bar / donut) uses a ~9-hue category palette — a greyscale split of 8+ categories is unreadable. Colour appears there and nowhere else (V-11). Renamed cards: “Financial Health” → “This month”, “Spending Distribution” → “Where it went”, “Expenses” → “Day by day”.
  • Icon library is a deferred decision. With no colour, the icon carries category identity, so a proper set (Lucide / Phosphor / SF Symbols / custom) is needed — the prototype uses rough placeholders. Blocking before SPEC-UI-UX.md §3.
  • Transactions tab icon is a clock / history glyph, not a receipt.
  • Amount keypad below, button below that. In the Add / Confirmation / Edit sheets the custom numeric keypad is amount-only, docked at the bottom with the primary action button pinned below it. Account / Note / Description raise the system keyboard instead, and the amount holds full height until the body is scrolled down to the fields, then collapses to a slim summary bar.
  • Type: Manrope + Geist. Manrope on headings and every figure (amounts, balance, counts); Geist on all other UI text.
  • The raw SMS is never shown or stored. The parser reads the message in memory to pre-fill fields, then discards it (impl. P-9); a detected transaction's Details carries only a quiet “Detected automatically” provenance line.
  • Kept: ₹ + Indian grouping + leading sign; permission banner on Home + Review Queue (a neutral hairline banner, no tint).
